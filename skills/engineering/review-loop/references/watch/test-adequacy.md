# Watch-list: Test adequacy

Attach when the diff adds or changes tests, or when the goal lists acceptance criteria or required tests.

Apply after coverage enumeration, using the common worker brief's reporting format and the supplied evidence rules.

TA2 and TA9 default to a one-off mutation in a disposable scratch copy. Ordinary fixes need no saved patch or coordinator replay for this check. Only when mutation is infeasible, state why and give a complete cited argument for test discrimination; this fallback does not waive required execution of the boundary or mandatory replayable proof.

- **TA1 Tests reach the production path.** Do tests exercise the real transport, router, SQL, and wiring, rather than a mock that replaces the code under review? An e2e label does not establish coverage when the tested route is intercepted or mocked. **Verify:** trace each acceptance test to its claimed boundary and list substitutions, including browser route interception. Send the real client's request through the actual handler; a test of unrelated UI behavior may use a mock but cannot close a server-contract finding.
- **TA2 No tautological doubles.** Would the test detect incorrect production logic, or does the mock simply return the expected answer? **Verify:** mutate the relevant production logic in a scratch copy and run the named test; confirm failure at the intended assertion, not during setup. Trace the production path and use the fallback above only if mutation is infeasible. List tests that survive the relevant mutation under `Low-signal tests`, with a harden or delete recommendation.
- **TA3 Fixtures use real values.** Do fixtures use the dependency's real units and defaults (ms or s, real limits)? **Verify:** compare fixture values against library source or defaults.
- **TA4 Regression tests survive fixes.** Does a fix delete or weaken the only test for an earlier defect? **Verify:** list the tests the diff removes or rewrites and map each one to a ledger ID.
- **TA5 Contention tests are concurrent.** Do contention tests start actors in parallel behind a barrier and assert the required exclusion or ownership outcome? Tests that run serially do not count. **Verify:** inspect scheduling and assertions, then run the real concurrent case. Remove the guard in a scratch copy if discrimination remains uncertain or the risk-scaled proof procedure requires it; ordinary contention evidence does not require a saved fault patch by default.
- **TA6 Required tests exist.** Does each required crash, SIGKILL, overlap, actor-matrix, and boot test named by the goal exist, and does each run against the production path? **Verify:** map each acceptance criterion to a test name and command.
- **TA7 The gate runs.** Are new suites wired into CI or the verify command? Are tests deterministic, with no dependence on poll timing or nondeterministic probes? **Verify:** find the CI line that invokes each suite. Run it several times.
- **TA8 Reports are measurements.** Do performance or latency claims come from real measurements, not counters or estimates? **Verify:** rerun the command and inspect the raw data.
- **TA9 Tests pass for the right reason.** Does each negative test assert the specific error kind or outcome, so that setup failure or an unrelated rejection cannot satisfy it? **Verify:** check assertion specificity and production-path reachability, then break the guard in a scratch copy and confirm the named test fails for the intended reason. Use the fallback above only if mutation is infeasible. If an unrelated failure can satisfy the test, list it under `Low-signal tests`.
- **TA10 Security dependencies are active.** Does the test environment actually execute the sanitizer, validator, cryptographic check, or other security library, with the capabilities it needs? **Verify:** run a known-hostile input through the pinned dependency in this runtime, assert that the protection changes/rejects it, and disable that protection in a scratch copy to make the test fail. A DOM shim or fallback where the library is inert is not evidence for the browser/server security boundary.
- **TA11 Async and static guards discriminate.** Do lifecycle tests use real pending I/O where settlement/ownership is the property, and do static guard tests detect a statement moved outside its required lock even with its tag intact? **Verify:** apply lifecycle-and-shutdown LS10 and concurrency-and-state CS12. Record mock-only evidence as unverified for those properties.
- **TA12 Cited tests really execute.** Do reports name existing tests that the given filter selects, and do regression checks actually rerun rather than replay cached output? **Verify:** inspect test discovery and selected counts, and bypass task-result caches. When fault-patch replay is required or supplied, replay it in isolation: the intended assertion must fail, then the restored test must pass with an identical source tree. Ordinary regressions need no fault patch merely to satisfy this entry.
