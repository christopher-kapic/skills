# Watch-list: JavaScript and TypeScript runtimes (Node.js, Workers, Bun, Deno)

Attach when the diff touches JavaScript or TypeScript runtime code. Pair it with the class lists; this list covers language and runtime traps.

Apply after coverage enumeration, using the common worker brief's reporting format and the supplied evidence rules.

- **JS1 String length units.** `.length`, `slice`, and Zod `.min`/`.max` count UTF-16 code units. JSON Schema `minLength`/`maxLength` count code points. Byte limits need `Buffer.byteLength` or `TextEncoder`. Does each limit use the unit the spec names? **Verify:** test at the boundary with astral and multi-byte characters.
- **JS2 Case, collation, and trim.** `toLowerCase()` is not case folding. `<` and `localeCompare` are not database collation. `trim()` strips NBSP and BOM. Do identity keys and sort keys avoid all three? **Verify:** search for these calls on identity or sort keys and test NBSP, BOM, and multi-character folds.
- **JS3 Dates.** `Date` has millisecond precision, `Date.parse` accepts non-ISO strings, and string comparison of ISO timestamps is not chronological across offsets. **Verify:** check where timestamps are parsed and compared, and test sub-millisecond, offset, and invalid inputs.
- **JS4 Prototype keys.** Can user-supplied keys read inherited properties (`constructor`, `toString`) or change an object's prototype (`__proto__`) through `in`, bare indexing, or assignment? **Verify:** read and write the keys `constructor` and `__proto__`, then check both the value and `Object.getPrototypeOf(obj)`. Leads: `Object.hasOwn` makes lookups safe, but not writes, because assigning `obj["__proto__"]` still calls the inherited setter. `Map`, `Object.create(null)`, and `Object.defineProperty` avoid the setter.
- **JS5 Replacement patterns.** Does `String.prototype.replace` or `replaceAll` receive a string replacement built from user data, where `$$`, `$&`, `` $` ``, `$'`, `$n`, and `$<name>` are interpreted? **Verify:** put `$&` and `$'` in user content. A function replacement avoids this.
- **JS6 Options spread over validated fields.** In `{ ...validated, ...callerOptions }`, the caller overrides validated URL, host, path, or auth fields. **Verify:** pass each validated field in the caller options.
- **JS7 Floating promises.** Does every fire-and-forget promise (heartbeats, timers, background loops) have a handler that routes into the retry or state machine? Node terminates the process on unhandled rejections by default. **Verify:** search for un-awaited calls and make each one reject.
- **JS8 Memoized promises.** Does a cached init or drain promise stay resolved, or cache a rejection forever, and so miss later work? **Verify:** call the memoized function again after the first promise settles, with new work pending.
- **JS9 Blocking the event loop.** Do request paths call `execSync`, `spawnSync`, `*Sync` filesystem APIs, or run CPU-heavy loops per request? **Verify:** search for `Sync(` in request paths and load-test concurrent requests.
- **JS10 Stream modes.** Can data be lost because the stream flows with no `data` handler (after `resume()`, or after the handler is removed), or can a byte limit be miscounted after `setEncoding()` turns chunks into strings? **Verify:** test size limits with `setEncoding('utf8')` and multi-byte data, and check every path that resumes or pipes the stream before a consumer is attached.
- **JS11 AbortSignal.** Is `signal.aborted` checked before starting, given that an `abort` listener added after abort never fires? **Verify:** pass `AbortSignal.abort()` and assert that no work is dispatched.
- **JS12 Regular expressions.** Are user-influenced regexes free of catastrophic backtracking, of stateful `lastIndex` with the `g` or `y` flags, and of `u`/`v` flag semantic changes? **Verify:** time pathological inputs, and reuse a global regex across calls.
