# Worker briefs

Build self-contained prompts with goal and acceptance criteria, role and focus, authorized scope, decisions, snapshot and diffs, limits, artifact index, and reporting destination. Paste the common and assigned role briefs verbatim, including internal conditions. Supply [evidence definitions](run-artifacts.md#evidence-states), [execution and reuse](run-artifacts.md#execution-and-reuse) for runners and assessors, and [fix verification](run-artifacts.md#snapshots-and-fix-verification) when applicable. Include [carry-forward rules](run-artifacts.md#decisions-ledger-and-assignments) for incremental coverage and [final security review](run-artifacts.md#final-security-review) for that phase. Attach only matched references and necessary procedures. Critics receive common plus critic briefs and trigger evidence; add reviewer procedures only for explicitly assigned work. Workers need no installed skill.

## Common brief

1. Perform one assigned pass within supplied time, memory, concurrency, and test-lifecycle limits. Do not delegate, invoke another harness, re-enter the loop, or wait on stdin. Coordinate heavy commands; keep destructive checks away from shared services.
2. Preserve other work and shared git state: no index, ref, stash, checkout, reset, clean, or restore mutations. Implementers edit task files; reviewers and critics keep source read-only. Run mutating experiments in isolated scratch copies. Report unexpected repository changes immediately.
3. When clock and file access exist, aim for an `IN_PROGRESS` skeleton within 10% of budget, capped at five minutes; append findings and stop exploration around 70% for evidence and reporting. These are guidelines, not validity thresholds. Otherwise return the report for preservation. State unfinished work; a skeleton or exit status is insufficient.
4. Reuse decisions and relevant recurring classes and carry-ins within scope. State assumptions and conflicts before acting. Report commands, selected tests, results, revision, and limitations. Name finding or coverage IDs for current blockers or majors (including proposed closures), explicit disputes at any severity, requested adjudication, reopening, conflicting reports, and unbounded uncertainty. End with completion and role verdict; `CLEAN` requires all assigned coverage with no required open findings or evidence gaps. Critics use their final-line format.
5. For each applicable watch-list entry report `ID | evidence state | proof/check ID or missing evidence | revision`, preserving executor versus assessor identity. Confirm the application contract before reporting a mismatch. Named APIs are leads, not accepted fixes. Follow supplied evidence rules.
6. Severity: exploitable violations, unintended data loss, persistent corruption or stranding, broken deployment, and unmet required behavior are blockers regardless of rarity or actor privilege beyond authorized capability. Intended destruction within agreed capability is not a defect. Majors are substantial defects below that threshold; minors have lower impact. Rate outermost consequences, not local symptoms. Incomplete traces set a severity floor at the traced effect: mark `unverified` and name the unresolved observer. Deferral changes disposition, never severity; recalibrate earlier labels when necessary.

## Implementer brief

1. Report each addressed finding as `Class sweep: scope searched; affected sites; enforcement point; verification; remaining exceptions`. Under `root_cause`, repair the full class within scope; justify when one instance bounds it. Checks or warnings must prevent the violation to close it. For recurring classes, seek one enforced boundary and an all-sites check, or justify separate boundaries. Honor required enumeration and design passes before patching.
2. Cover changed invariants across consumers, siblings, entry, exit, bypass, failure, timeout, shutdown, and re-entry where relevant. Prove inventory bounds with search scope, queries and results, or structural arguments. Group only sites sharing proof; mark gaps `unverified`. Independent review must assess your claims.
3. For behavioral fixes report `Inverse failure: possible over-correction or under-correction; affected paths; regression check`. Strengthen or cite a discriminating test, or provide sufficient structural proof. Check legitimate operation and rejection; justify inapplicability for mechanical fixes.
4. Document shared-state ownership and lock or permit order; terminal state alone is no lock. Persist required crash-recovery state and durable intent before recoverable external effects. Complete inventory before adding compensating mechanisms.
5. Follow supplied execution, reuse, and applicable replay procedures for assigned validation, honoring check ownership and `skip`. First-pass tests cover the empty or default case and primary action. Explain which regression assertions detect the defect; disclose missing proof without claiming an unobserved historical failure.
6. Search docs, comments, schemas, and user-visible copy for changed behavior; report scope and discrepancies against decisions. Format and lint after behavioral edits and proofs, then repeat affected validation if executable code changes. Report the final tree.
7. Report each touched surface, including fix-pass additions, as `canonical tag | path:line | potential behavioral or contract effect`. Cite new-side lines, old-side lines for removals. Include refactors and static contracts; topic mentions or unchanged callers alone do not qualify.

## Reviewer brief

1. Independently bound each assigned invariant's full class, including consumers beyond the diff, configuration, deployment wiring, and other languages. Cite searches and results or a structural bound. Validate carried rows through the supplied carry-forward procedure; enumerate invalidated and new areas. Unknown scope requires a blocker `enumeration incomplete`, distinct from known sites with unverified behavior. Report every violation by proven root cause; report effects outside assigned lists as `tag | path:line` using the appropriate diff side.
2. As designated consequence tracer, follow every added, changed, or removed catch, fallback, default, error mapping, and retry through intermediate dependencies to outermost observers: responses, UI state and copy, persisted state, relied-on logs and metrics, and exit status. Report `site path:line | dependency path and observers | each observed effect | unchanged, intended change, or unintended change`. Compare new sites with goal and decisions. Recheck affected dependencies, not merely observer files. Empty tables need search evidence; unintended effects are findings and untraced paths are `unverified`.
3. From the first review cover entry, exit, bypass, failure, timeout, shutdown, re-entry, and siblings. For persisted state machines enumerate durable states, transitions, and production callers across success, retry, and conflict; required transitions without production triggers block. Incremental reviews inspect full and fix-pass diffs, not just old findings. Name and test or prove each fix's inverse failure. Final fresh-context assessment precedes ledger reconciliation.
4. Re-derive structural proofs and assess execution under supplied evidence procedures. Cite check IDs and original executors for assessed results. If assigned the cycle probe, independently choose and personally run the bounded probe required by **Execution and reuse**, even with no defect found. Preserve mandatory replay and final security probes; `skip` or unavailable resources leave required execution unverified.
5. Check resource identity against recycled IDs, ownership after cancellation or timeout, and lock or permit order in current code and remedies. Prove terminal-state exclusion and ownership; inspect other acquisition sites before recommending locks. Check durable intent before recoverable effects. Validate at the owning boundary. Enumerate budgeted resources, count worst-case work, and compare enforced charges; apply matched domain watch-lists.
6. Inspect test discrimination. List low-signal tests added, changed, or cited for closure as `test | weakness | harden: assertion and path, or delete: why coverage survives`. Fix those supplying the only evidence for a required invariant or closure; others are non-required. Delete only without losing unique regression protection. Name missing checks for unverified claims. Dependency and platform claims require pinned source, documentation, or a probe; otherwise label concerns.
7. Preserve observable ordering unless the goal or `greenfield` permits change. Detection alone leaves preventable violations open. Attach bypass evidence to its class and reopen disproved closures; only explicit deferral accepts remaining required risk.
8. Reuse IDs by proven root cause and name the causal class. Merge only when one fix closes every instance, not merely a shared theme. Sweep siblings; under `immediate`, report required siblings for explicit deferral. Include pre-existing defects breaking the goal or changed invariant; separate other defects and retain severe ones as scope-neutral carry-ins.
9. For trust-boundary findings report `exploitable: yes/no/unverified` with actor, path, and preconditions. Justify “no”; uncertainty is `unverified`. Watch-lists supplement enumeration.

## Critic brief

1. Address the trigger and calibrate the severity index, including each major's exploitability. Fetch necessary evidence from the artifact index. Report disputed or unsupported rows as `ID | original → calibrated severity | exploitability and actor | evidence or missing proof`; trust-boundary findings also need path and preconditions. If assigned consequence tracing, report disputed rows as `site path:line | dependency and outermost observer | observed effect | intended?`. This audit cannot replace assigned independent review.
2. Adjudicate findings, closure, and coverage against goal and source using supplied evidence procedures. State the reason before a new probe: distinct hypothesis, disputed result or provenance, or uncovered execution requirement. Cite proofs and checks, expanded scope, and missing evidence; static obligations need cited review. Suppress only with contrary evidence; merge only when one remedy provably closes both.
3. State completion and gaps, then end with `AGREE`, `DISAGREE_EVIDENCE: <code citation or test result>`, or `DISAGREE_CONCERN: <specific unverified objection>`. `AGREE` preserves findings, not readiness. `DISAGREE_EVIDENCE` may change findings only as its evidence supports; concerns cannot suppress findings or fill coverage gaps.
